機器學習基礎

這一章是所有後續章節的「文法」——監督式 vs 非監督式、過擬合、bias-variance、AUROC vs AUPRC、特徵重要性。我們用乳癌與糖尿病兩個真實生醫資料集示範，並用三個互動 widget 把抽象概念變直覺。

核心概念

一、監督式 vs 非監督式 vs 自監督式

機器學習的本質是從資料學一個函數。三大典範的區別在於訓練時是否提供正確答案 (label)：

監督

監督式學習

有 X 也有 y。每筆訓練樣本都有正確答案。

像小孩學認字——大人指著「貓」的圖告訴他「這是 cat」，重複幾千次後他就能認新圖。
非監督

非監督式學習

只有 X 沒有 y。模型自己找出資料結構。

像把一堆水果倒桌上要小孩自己分類——標準不只一個。
自監督

自監督式學習

只有 X，但模型自己「造 label」當 pretext 任務學。ESM、DNABERT、scGPT 都用這套。

像填空題自學——對 6.5 億條蛋白序列遮 15% 字要自己猜，就學會了「演化的語法」。
💡
為什麼自監督這麼重要？因為「有 label 的生物資料」稀缺而昂貴（需要實驗驗證），但「沒 label 的序列」滿地都是（UniProt 已有 ~2.4 億條蛋白序列）。自監督讓我們能榨乾這 99% 的「免費資料」。fine-tune 階段再用少量 label 就能達到很好的下游任務表現——這就是「foundation model」的商業模式。 Why does self-supervision matter so much? Labeled biological data is scarce and expensive (requires experiments), but unlabeled sequences are everywhere (UniProt has ~240M protein sequences). Self-supervision lets us squeeze the 99% of 'free data.' Then fine-tuning with a small labeled set achieves great downstream performance — this is the foundation-model business model.
工作流程

二、Train / Validation / Test 切分（與生資特有的陷阱）

三組資料各自的角色：

  • Train (~70%)：模型用來學參數的資料。
  • Validation (~15%)：用來挑選超參數 (hyperparameter)、early stopping、模型選擇。絕不能用來報告最終表現。
  • Test (~15%)：模型「真正沒看過」的資料，只在最後一次評估。

但生資中要特別小心 data leakage——同樣的「過擬合假象」可能來自切分本身：

Three roles:

  • Train (~70%) — fits the parameters.
  • Validation (~15%) — picks hyperparameters / early stopping / model selection. Never report performance from here.
  • Test (~15%) — held-out, evaluated only once at the very end.

But in biology, beware of data leakage — the same overfitting illusion can come from the split itself:

切分方式風險正確做法
隨機 split 同一病人多筆樣本可能同時出現在 train 與 test Group K-fold 以 patient_id 分組
序列任務隨機切 同源序列跨組 Sequence-identity split
時間序列隨機切 用未來資料訓練預測過去 Temporal split
特徵中含 ID 模型學會 ID 捷徑 嚴格 audit 特徵清單
🚨
真實案例：2019 年某「肺癌 X-ray 預測 AUROC 0.95」論文被踢爆——模型其實學會了識別哪台 X-ray 機器，而醫院剛好把不同階段的患者送到不同機器（confounding）。在另一家醫院測試 AUROC 跌到 0.55。分組切分能擋掉 90% 這類錯誤。 True story: a 2019 paper claimed 'AUROC 0.95 for lung cancer X-ray' — until it was revealed the model had learned to identify which X-ray machine was used, and the hospital sent patients to different machines based on stage (confounding). At a second hospital AUROC dropped to 0.55. Group splits prevent 90% of such errors.

深入理論

四、Bias-Variance Tradeoff

任何 ML 模型的誤差都可拆解為 Bias² + Variance + Irreducible noise 三項。

高 Bias (Underfitting)

模型太簡單，連訓練集都學不好。train loss 高、val loss 也高。

像用直線擬合 sin 波——再多資料都救不了。

高 Variance (Overfitting)

模型太複雜，記住了訓練集的雜訊。

像背標準答案的學生——遇到變形題就完蛋。
💡
奇妙的「double descent」現象：傳統理論認為模型超過某容量後 val loss 會單調上升，但 2019 年 Belkin 等發現在極度過參數化（參數 ≫ 訓練樣本）的範疇下，val loss 會「再次下降」——這正是為什麼 ESM-2 15B 比 ESM-2 8M 更準。AI for biology 已經處在這個「神奇地帶」。 The surprising "double descent": classical theory says val loss rises monotonically past some capacity, but Belkin et al. (2019) found that in the extremely overparameterized regime (params ≫ samples), val loss falls again — which is exactly why ESM-2 15B beats ESM-2 8M. AI for biology now lives in this "magic zone."

⚠️
1:200 罕見疾病的數字遊戲：假設你閉著眼睛說「全部陰性」，accuracy 已經 99.5%、AUROC 可以隨機，但 AUPRC 接近 0。這就是為什麼罕見疾病模型只看 AUROC 會非常危險。一個 AUROC=0.95、AUPRC=0.20 的模型在 deployment 時，每 5 個陽性預測會有 4 個是假警報。Saito & Rehmsmeier (2015) 是這個議題的經典論文。 The 1:200 rare-disease numbers game: if you blindly predict 'all negative,' accuracy is already 99.5% and AUROC can be random — but AUPRC is near 0. This is why looking only at AUROC for rare diseases is dangerous. A model with AUROC=0.95 and AUPRC=0.20 will deliver 4 false alarms per 5 positive predictions in deployment. Saito & Rehmsmeier (2015) is the classic reference.
動手實作

六、Wisconsin 乳癌資料集對戰

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.linear_model import LogisticRegression
from sklearn.ensemble import RandomForestClassifier
from xgboost import XGBClassifier
from sklearn.metrics import roc_auc_score, average_precision_score, matthews_corrcoef

X, y = load_breast_cancer(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

models = {
    "LogReg": LogisticRegression(max_iter=5000, C=1.0),
    "RandomForest": RandomForestClassifier(n_estimators=300, random_state=42),
    "XGBoost": XGBClassifier(n_estimators=300, learning_rate=0.05, max_depth=4,
                            use_label_encoder=False, eval_metric="logloss")
}
for name, mdl in models.items():
    mdl.fit(Xtr, ytr)
    p = mdl.predict_proba(Xte)[:, 1]
    yhat = (p >= 0.5).astype(int)
    print(f"{name:14s}",
          "AUROC", round(roc_auc_score(yte, p), 3),
          "AUPRC", round(average_precision_score(yte, p), 3),
          "MCC",   round(matthews_corrcoef(yte, yhat), 3))

# Typical output:
# LogReg         AUROC 0.997  AUPRC 0.998  MCC 0.94
# RandomForest   AUROC 0.992  AUPRC 0.995  MCC 0.93
# XGBoost        AUROC 0.996  AUPRC 0.997  MCC 0.94
library(tidymodels); library(mlbench); data("BreastCancer")
df <- BreastCancer |> na.omit() |> mutate(across(2:10, as.numeric))

split <- initial_split(df, prop = 0.8, strata = Class)
tr <- training(split); te <- testing(split)

rec <- recipe(Class ~ ., data = tr) |> step_rm(Id) |> step_normalize(all_numeric_predictors())

mods <- list(
  logit = logistic_reg() |> set_engine("glm"),
  rf    = rand_forest(trees=300) |> set_mode("classification") |> set_engine("ranger"),
  xgb   = boost_tree(trees=300, learn_rate=0.05) |> set_mode("classification") |> set_engine("xgboost")
)
workflow_set(list(rec=rec), mods) |>
  workflow_map("fit_resamples", resamples = vfold_cv(tr, v = 5, strata = Class),
               metrics = metric_set(roc_auc, pr_auc, mcc)) |>
  collect_metrics()

這個資料集太簡單，三個模型差不多。真實 tabular 任務 XGBoost/LightGBM 通常勝出，但 Logistic 在臨床仍受青睞——可解釋性壓過精度。

模型可解釋性

七、SHAP：把黑盒打開

SHAP 把每筆預測拆解成各特徵貢獻，是臨床/監管 model card 的標配。

import shap, xgboost as xgb

mdl = xgb.XGBClassifier(n_estimators=300).fit(Xtr, ytr)
explainer = shap.TreeExplainer(mdl)
shap_values = explainer.shap_values(Xte)

# Global: which features matter most?
shap.summary_plot(shap_values, Xte, feature_names=feature_names)

# Local: explain a single prediction
shap.force_plot(explainer.expected_value, shap_values[0], Xte[0])

# Force plot 會顯示：base_value 0.4 → 此樣本 0.92，
# 哪些特徵把預測推高、哪些壓低，每個貢獻多少。
💡
SHAP 的兩個常見誤用：(1) 把 global feature importance 跟個案的 local explanation 混淆——前者是「整體上哪些特徵重要」，後者是「對這個病人為什麼預測這樣」；(2) SHAP 顯示相關性不是因果性，不能直接用來做機制推論。 Two common SHAP misuses: (1) confusing global feature importance with per-case local explanations — the former is 'overall, what matters,' the latter is 'why this patient got this prediction'; (2) SHAP shows association, not causation — don't infer mechanism directly from it.

八、選哪個 ML 模型？

🌳 Quick guide

N<1k → Logistic / Penalized regression（可解釋、不易過擬合）
1k-100k → XGBoost / LightGBM 是 tabular 王者
>100k → 序列/影像跳到 DL（章 03），tabular 仍 GBM
無標籤 → K-means / Louvain → UMAP 視覺化
極不平衡 → class_weight / focal loss / SMOTE
臨床部署 → 必須 calibration + SHAP + 子群指標
深入討論

九、爭議：經典 ML 真的會被 DL 取代嗎？

Shwartz-Ziv & Armon (2022) 在 11 個 tabular benchmark 上發現：XGBoost 平均優於各種 DL 架構（TabNet、SAINT、FT-Transformer）。原因可能是 tabular 特徵已被人類「工程過」，沒有像 raw 序列 / image 那樣需要學表徵。

Shwartz-Ziv & Armon (2022) showed across 11 tabular benchmarks: XGBoost on average beats various DL architectures (TabNet, SAINT, FT-Transformer). The reason is likely that tabular features are already "human-engineered" — no need to learn representations from scratch like raw sequences or images.

DL 的優勢在「能自動學表徵」，但這對小 N 與良好工程的特徵反而是負擔。在生資中，真正適合 DL 的場景是：序列 (Ch 04-05、08-10)、影像 (病理切片)、單細胞表達矩陣，以及「沒有明顯特徵工程方向」的 raw 資料。

DL's edge is learning representations automatically — but that's a burden with small N and well-engineered features. In bio, DL truly wins on: sequences (Ch 04-05, 08-10), images (pathology slides), single-cell matrices, and other raw data without an obvious feature-engineering path.

現在大部分高表現 pipeline 是「foundation model 抽 embedding → 經典 ML 分類」：例如把 ESM-2 嵌入丟給 XGBoost 預測抗體親和力。這比 fine-tune 整個 Transformer 便宜 100×，效果只差 1-2 個百分點。對小實驗室是甜蜜點。

Most high-performing pipelines today are "foundation model embeddings → classical ML classifier": e.g., feed ESM-2 embeddings to XGBoost for antibody-affinity prediction. 100× cheaper than fine-tuning the whole Transformer, with only a 1-2-point accuracy gap. The sweet spot for small labs.

Q1. 罕見疾病資料 (1:200 不平衡)，AUROC=0.95 但 AUPRC=0.20。最合理的解讀？

(A) 模型表現極佳
(B) 排序能力 OK，但實際應用 precision 仍很低
(C) 資料一定有 bug
(D) AUPRC 沒有意義可忽略
✅ 正解 (B)

Q2. 下列哪一種切分最容易導致「假好」表現？

(A) 對病人 ID 做 group K-fold
(B) 隨機 split — 同一病人在 train 與 test 各出現一次
(C) 序列相似度 30% 切分
(D) Stratified K-fold
✅ 正解 (B)

Q3. 自監督式模型最大的優勢是？

(A) 不需要算力
(B) 可利用海量無標籤序列預訓練，再以小量標籤 fine-tune
(C) 永遠比監督式準
(D) 不需要驗證集
✅ 正解 (B)。所有現代生物 foundation model 都採此設計。

Q4. train loss 很低、val loss 很高。最該嘗試？

(A) 加深模型
(B) 增加正則化（dropout、weight decay、early stopping）或加更多資料
(C) 降低正則化強度
(D) 加更多特徵
✅ 正解 (B)。這是過擬合典型徵兆。

Q5. 對臨床部署的 ML 模型，下列哪一項不是必備？

(A) Calibration
(B) SHAP 個案解釋
(C) 多族群 disaggregated 指標
(D) 必須使用 GPU 訓練
✅ 正解 (D)。GPU 只是算力選擇，與臨床合規無關。
