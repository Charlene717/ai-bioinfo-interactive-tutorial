生醫大型語言模型

BioGPT、BioMedLM、Med-PaLM 2、GPT-4 醫學評估、Evo 2 跨模態：LLM 在生醫文獻挖掘、臨床問答、序列推理上的能力與盲點。

BioGPT, BioMedLM, Med-PaLM 2, medical GPT-4 evaluation, cross-modal Evo 2: what biomedical LLMs can and cannot do in literature mining, clinical QA, and sequence reasoning.

必修技巧

二、RAG：對抗 hallucination 的核心武器

LLM 直接回答醫學問題容易「幻覺 (hallucinate)」——記錯藥名、引用不存在的論文。RAG 透過先檢索可信知識庫 (PubMed、UpToDate、ClinVar)，再讓 LLM 基於檢索結果生成答案，把生成「錨定」在來源上。

典型流程：

  1. 把所有 PubMed 摘要切成 ~500 字 chunk，用 embedding 模型 (e.g. text-embedding-3-small 或 BGE-large-en) 編碼成向量。
  2. 存入向量資料庫 (FAISS、Qdrant、Weaviate)。
  3. 查詢時：embed query → top-k 檢索相關 chunk → 把 chunk 拼進 prompt 給 LLM。
  4. LLM 生成答案並引用來源 chunk。

Bare LLMs hallucinate — wrong drug names, fabricated citations. RAG retrieves trustworthy knowledge (PubMed, UpToDate, ClinVar) first, then conditions the LLM on those passages, anchoring the generation to sources.

Typical flow:

  1. Chunk all PubMed abstracts into ~500-token blocks; embed with text-embedding-3-small or BGE-large-en.
  2. Store in a vector DB (FAISS, Qdrant, Weaviate).
  3. At query time: embed query → top-k retrieve → concatenate chunks into the LLM prompt.
  4. LLM answers with citations.
動手

三、最小可運行的 PubMed RAG

# pip install langchain langchain-openai chromadb pubmed-parser
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings, ChatOpenAI
from langchain.vectorstores import Chroma
from langchain.chains import RetrievalQA
import pubmed_parser as pp

# Step 1: Build vector DB from a PubMed XML dump
docs = pp.parse_medline_xml("pubmed24n0001.xml")
texts = [d["abstract"] for d in docs if d["abstract"]]

splitter = RecursiveCharacterTextSplitter(chunk_size=800, chunk_overlap=100)
chunks = splitter.create_documents(texts)
db = Chroma.from_documents(chunks, OpenAIEmbeddings(), persist_directory="./pubmed_db")

# Step 2: Query with citations
qa = RetrievalQA.from_chain_type(
    llm = ChatOpenAI(model="gpt-4o-mini", temperature=0),
    retriever = db.as_retriever(search_kwargs={"k":5}),
    return_source_documents = True
)
ans = qa("What does scGPT contribute to perturbation prediction?")
print(ans["result"])
for d in ans["source_documents"]: print(d.metadata.get("source"))
# Local & private — no data leaves your machine
# 1. ollama pull llama3.1:8b-instruct  (or mistral, qwen)
# 2. pip install langchain chromadb sentence-transformers

from langchain_community.llms import Ollama
from langchain_community.embeddings import HuggingFaceEmbeddings
from langchain.vectorstores import Chroma

emb = HuggingFaceEmbeddings(model_name="BAAI/bge-large-en-v1.5")
db  = Chroma(persist_directory="./pubmed_db", embedding_function=emb)
llm = Ollama(model="llama3.1:8b-instruct", temperature=0)

陷阱

四、用 LLM 做生醫的五大坑

🌀 假引文

LLM 會「編造看起來像真的」DOI 與作者。應強制 RAG 模式並驗證每個引文存在於 PubMed。

LLMs invent plausible-looking DOIs and authors. Enforce RAG and verify each citation against PubMed.

📅 知識截止

LLM 不知道訓練後發生的事。新藥、新指南、新基因都需 RAG 補。

LLMs don't know post-training events — new drugs, guidelines, genes. Bridge with RAG.

🔒 PHI / HIPAA 隱私

不能把病歷送到外部 API。應用本地 Ollama / vLLM + 加密向量庫。

Never send EHR to external APIs. Use local Ollama / vLLM + encrypted vector store.

🧪 Benchmark 污染

主流 medical QA benchmark 多已被各家 LLM 看過。論文宣稱的 90%+ 準確率須以「自家未洩漏資料」驗證。

Mainstream medical QA benchmarks have likely leaked into LLM training data. Validate claimed 90%+ on your own held-out set.

序列 LLM

五、Evo 2：當 LLM 學會「DNA 語言」

2025 年 Arc Institute 與 NVIDIA 發表 Evo 2：基於 StripedHyena 架構、9 兆 nt 訓練、最大 40B 參數、1M 上下文窗口。能做：

  • 零樣本變異效應：對 BRCA1 致病性變異無需 fine-tune 也能正確排序。
  • 跨界生成：一次生成完整粒線體基因組或細菌 operon。
  • 單核苷酸解析的 likelihood 推算 (vs DNABERT 的 6mer 平均)。

但 Evo 2 不是萬能：對人類 GWAS 個體變異仍弱，2025 年 8 月的 BioRxiv 提示其在 personal expression 任務只比 baseline 略好。

Evo 2 (Arc Institute & NVIDIA, 2025): StripedHyena architecture, 9 trillion nt of training, up to 40B parameters, 1M-token context. Capabilities:

  • Zero-shot variant effect: ranks BRCA1 pathogenicity correctly without fine-tuning.
  • Cross-domain generation: produce a complete mitochondrial genome or bacterial operon in one shot.
  • Single-nucleotide resolution likelihood (vs DNABERT's 6-mer averages).

Not a silver bullet: weak on human GWAS individual variants — an Aug-2025 BioRxiv noted only marginal improvement on personal expression tasks.
