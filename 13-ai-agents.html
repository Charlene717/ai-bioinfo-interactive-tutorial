生資 AI Agents 與工作流

CRISPR-Agent、Variant Triage Bot、AutoBio：把 LLM、工具呼叫、資料庫、實驗自動化串成「能自己思考的助理」。

CRISPR-Agent, Variant Triage Bot, AutoBio: chaining LLMs, tool calls, databases, and lab automation into a thinking assistant.

什麼是 Agent

一、Agent ≠ 對話 LLM

一個 LLM agent 至少包含三個組件：

  • 規劃 (Planner)：拆解使用者的高階目標成步驟。
  • 工具 (Tools)：可呼叫的外部函式 (BLAST、SpliceAI、Ensembl REST、shell 等)。
  • 記憶 (Memory)：scratchpad、向量檢索的長期記憶；用於跨步驟一致性。

三者經由「ReAct」(Reason + Act) 或「Plan-and-Execute」迴圈互動，使 agent 能根據前一步結果動態調整下一步。

An LLM agent has at least three parts:

  • Planner — decomposes a high-level goal into steps.
  • Tools — callable external functions (BLAST, SpliceAI, Ensembl REST, shell, etc.).
  • Memory — scratchpad and vector-retrieved long-term memory for cross-step consistency.

They interact via ReAct (Reason + Act) or Plan-and-Execute loops, letting the agent adjust based on prior results.

User goal → Plan → [Reason → Tool call → Observe] × N → Final answer + Audit trail
生資場景

二、四個高價值的生資 agent 場景

📋

變異篩查 Bot

輸入 VCF → 自動 annotate (VEP) → 跑 SpliceAI / AlphaMissense → 比對 ClinVar / OMIM → 整理 ACMG/AMP 證據 → 輸出可審核的 evidence table。NHS 已部署多個此類工具。

VCF in → auto-annotate (VEP) → run SpliceAI/AlphaMissense → cross-ref ClinVar/OMIM → assemble ACMG/AMP evidence → output an audit-ready table. Several NHS deployments exist.

🧬

CRISPR 設計 agent

給定基因 + 目標 (KO / KI / activation) → 規劃 gRNA → 跑 CRISPOR / Cas-OFFinder → 排序 → 設計 primer → 產生實驗 protocol。

Given a gene and goal (KO/KI/activation) → plan gRNAs → run CRISPOR/Cas-OFFinder → rank → design primers → produce a wet-lab protocol.

📊

自動分析腳本生成

「給我 5 個樣本的 scRNA-seq Seurat 分析腳本」→ agent 寫出可跑的 R/Python 流程，必要時調用容器執行。

"Give me a Seurat pipeline for 5 scRNA-seq samples" → the agent writes runnable R/Python, executing in a container if needed.

🔬

文獻 + meta 分析

對特定基因/疾病：抓 PubMed 摘要 + GEO/SRA 資料 → 統一 normalize → 做 meta DE → 自動寫成草稿。

For a gene/disease: pull PubMed + GEO/SRA data → harmonize → meta-DE → drafted as a write-up.

動手

三、用 LangChain 建一個迷你變異 triage agent

# pip install langchain langchain-openai requests
from langchain.agents import AgentExecutor, create_react_agent, Tool
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
import requests, subprocess, json

# --- Define tools ---
def vep_annotate(variant_str):       # e.g. "17:7676154:G:A"
    r = requests.get(f"https://rest.ensembl.org/vep/human/region/{variant_str}",
                     headers={"Content-Type":"application/json"})
    return json.dumps(r.json()[:1])

def spliceai_score(variant_str):
    out = subprocess.check_output(["spliceai", "-I", f"<(echo {variant_str})"], shell=True)
    return out.decode()

def clinvar_lookup(variant_str):
    r = requests.get(f"https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi",
                     params={"db":"clinvar", "term": variant_str, "retmode":"json"})
    return json.dumps(r.json())

tools = [
    Tool(name="VEP",       func=vep_annotate,   description="Annotate a variant"),
    Tool(name="SpliceAI",  func=spliceai_score, description="Get splicing impact score"),
    Tool(name="ClinVar",   func=clinvar_lookup, description="Search ClinVar")
]

# --- ReAct loop ---
prompt = PromptTemplate.from_template(
    "You are a clinical bioinformatics agent. {input}\n{agent_scratchpad}\n"
    "Available tools: {tools}\nNames: {tool_names}"
)
agent  = create_react_agent(ChatOpenAI(model="gpt-4o-mini"), tools, prompt)
exe    = AgentExecutor(agent=agent, tools=tools, max_iterations=8, verbose=True)

result = exe.invoke({"input": "Triage variant 17:7676154:G:A — is it pathogenic?"})
print(result["output"])

這個 demo 中，agent 會自己決定先呼叫 VEP 看在哪個基因，再呼叫 ClinVar 查資料庫，最後若需要再跑 SpliceAI。整個過程留下完整 tool-call log，可被審核。

In this demo the agent decides on its own to first call VEP, then ClinVar, then SpliceAI if needed. The full tool-call log is auditable.

風險

四、Agent 的常見災難模式

🚨
三個必須有的護欄：
1. step budget — 設定最大工具呼叫次數，避免 agent 死循環。
2. destructive action 黑名單 — 禁止 rm -rf、SQL DROP、外部寫入等。
3. human-in-the-loop — 高風險決策 (報告診斷、實驗訂單) 必須人類核準。 Three mandatory guardrails:
1. Step budget — cap max tool calls to avoid loops.
2. Destructive-action denylist — block rm -rf, SQL DROP, outbound writes.
3. Human-in-the-loop — humans approve high-risk decisions (diagnoses, experiment orders).

🔁 思考死循環

連續呼叫同個工具想拼湊不存在的資料；用 step budget + 重複偵測。

Repeatedly calls the same tool trying to invent data; mitigate with step budget + duplicate detection.

🌀 工具幻覺

編出不存在的工具名稱呼叫；prompt 內明確列舉合法工具，並 strict JSON。

Invents tool names; pin legal tools in the prompt and use strict JSON output.

🪤 Prompt injection

檢索結果中的惡意指令會劫持 agent。每次工具回傳須以「context」標註而非「instruction」。

Malicious text in retrieved content can hijack agents. Treat tool outputs as context, not instructions.

💸 成本失控

連續長 prompt → API 成本爆炸；務必加 token 計數與 abort 條件。

Long prompts blow up API bills; track tokens and add abort thresholds.

(C) 大模型才行
(D) 不需要 logging

(A) 服從新指令

(D) 通知 user 並退出
✅ 正解 (B)
